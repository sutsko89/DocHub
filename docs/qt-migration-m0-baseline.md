# EW.DocHub — миграция Tk → PySide6: этап M0, фиксация baseline

**Статус: запись результатов этапа M0. Код не изменялся. Дата прогона — 23.11.2026.**

Этап M0 — предусловия миграции интерфейса на Python + PySide6 / Qt
Widgets (архитектурное решение от 23.11.2026 зафиксировано в примечании
блока E-2 протокола `docs/protocol-section-e.md`: стандартная системная
рамка Windows, без самописного переноса и растягивания). План миграции
(этапы M0–M8) ведётся как отдельный документ и в репозиторий не
включается; здесь фиксируются только проверяемые факты, которые он
требует от M0:

* **К-1** — полный регресс pytest + smoke 358 на целевой среде
  Windows / Python 3.13;
* **К-2** — прогон блока E-4 протокола (старт, память, P-08) на целевой
  среде — «до»-цифры текущего Tk-интерфейса для будущих сравнений с Qt.

## 4. Windows-runbook: закрытие К-1 и К-2

Порядок для целевой машины (Windows, Python 3.13, рабочий каталог
`C:\bench`). Команды собраны из протокола `docs/protocol-section-e.md`
(разделы 5.2–6.1 и 8) под пин M0.

### 4.1 Дерево и окружение

```powershell
git clone https://github.com/sutsko89/DocHub C:\bench\DocHub
cd C:\bench\DocHub
git checkout 52d96eb09b09b288d8985d108273b81510943e30
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
```

### 4.2 К-1: регресс и smoke на Windows

```powershell
.\.venv\Scripts\python.exe -m pytest | Tee-Object C:\bench\m0-regression.txt
.\.venv\Scripts\python.exe smoke_test.py | Tee-Object C:\bench\m0-smoke.txt
```

Ожидание: около 855 passed и SMOKE OK — 358 проверок. Фактическое число
на Windows может отличаться на единицы: часть тестов закрепляет
не-Windows ветки (test_win_shell, test_single_instance — skipif по
`sys.platform`) и на Windows пропускается. Зафиксировать фактические
passed/skipped; при отклонениях код не править — приложить stdout как
есть (правило раздела 9 протокола).

### 4.3 База @10k и изолированный профиль

```powershell
.\.venv\Scripts\python.exe tools\generate_registry.py --out C:\bench\reg10k --records 10000
mkdir C:\bench\profile\DogovorGenerator
Copy-Item C:\bench\reg10k\database.db C:\bench\profile\DogovorGenerator\database.db
```

### 4.4 К-2: сеанс E-4 «после» (раздел 8 протокола)

```powershell
cd C:\bench\DocHub
$env:APPDATA = "C:\bench\profile"; $env:EWDOCHUB_PERF_LOG = "1"
.\.venv\Scripts\python.exe main.py
```

В приложении: открыть реестр, дождаться списка, подождать ~30 с
(воркер старта завершает сверку), сделать 3–5 сохранений договора и
спецификации; при открытом реестре снять WorkingSet и закрыть штатно
(крестик — буфер perf.log сбрасывается при выходе):

```powershell
Get-Process python | Select-Object Id,
  @{n='WS_MB';e={[math]::Round($_.WorkingSet64/1MB,1)}} |
  Tee-Object C:\bench\e4-ws-after.txt
```

Отчёты:

```powershell
.\.venv\Scripts\python.exe tools\bench_store_1a.py --report C:\bench\profile\DogovorGenerator\logs\perf.log | Tee-Object C:\bench\e4-after.txt
.\.venv\Scripts\python.exe tools\bench_docx_build.py --runs 10 --items 30 | Tee-Object C:\bench\e4-p08-after.txt
```

Чтение отчёта — п. 8.2 протокола: главная метрика — максимум
duration-записей главного потока (`startup.apply_*`, `startup.backup`,
`Перерисовка реестра`, `Чтение реестра`, `Запись .docx`) за 5 с после
`startup.built`, порог ≤ 100 мс. Старт «до появления окна / до отлипа» —
внешним секундомером, 3 прогона (п. 8.4 протокола).
