# История версий EW.DocHub

Все изменения описаны относительно пунктов «Плана_исправлений.md».

## 2.0.1 — 2026-11-19 (исправление)

* **Поиск по ИНН в карточке ИП.** Переключатель «Юр. лицо / ИП» не был привязан
  к переменной типа карточки (`ui.segmented` не передавала `variable` в
  `CTkSegmentedButton`), поэтому `_cp_type_var` всегда оставалась «Юр. лицо».
  «Заполнить по ИНН» у ИП читала пустое скрытое поле юрлица и требовала
  «10 цифр» — поиск не срабатывал; той же причиной сломалось бы и сохранение
  карточки ИП. Теперь переменная привязана к сегменту, режим определяется
  корректно для обоих типов. Исправление в `ui_macos.py::segmented` и
  `main.py::_build_counterparty_page`.
* Smoke-тест дополнен регрессионной проверкой: реальный клик по сегменту «ИП»,
  «Заполнить по ИНН» с подменённым DaData и контроль подстановки реквизитов
  ЕГРИП (ФИО, ОГРНИП, адрес) в поля карточки ИП.

## 2.0.0 — 2026-11-18 (этапы 7–9 плана: P3)

### Тесты (этап 7)
* pytest-набор `tests/` — 113 теста без интерфейса: golden-сверка шести
  печатных форм с эталонами (проверка отсутствия `{{...}}` — регрессия бага
  1.1), проверка диска после сохранения, восстановление реестра (битый/
  обрезанный/null-JSON, дубли id, `.tmp`, `.bad`, read-only папка, сироты),
  импорт на образцах `.docx`/`.xlsx` (ООО и ИП, дубликаты ИНН, `.doc`,
  битые файлы), DaData с моком `urlopen` (200/401/429/500/URLError/таймаут),
  `safe_filename` и безопасность путей, негативная логика.
* Golden-эталоны: `tests/golden/*.json`, перегенерация —
  `python tests/make_golden.py`.
* Покрытие (цель ≥ 70 %): `document_builder` 93 %, `services` 80 %,
  `document_importer` 80 %, `storage` 80 %.
* CI на GitHub Actions (Python 3.13): Linux — pytest + smoke под Xvfb,
  Windows — pytest. `requirements-dev.txt`.
* **Исправление, найденное тестами:** в импортере после написания
  «Индивидуальный предприниматель» отсутствовал разделитель в регулярке —
  ФИО ИП не извлекалось и карточка не создавалась автоматически.

### Документация (этап 8)
* README переработан: интерфейс соответствует фактическому (кнопки в шапке
  вместо «меню Файл» и бокового меню; поиск по названию и ИНН; удаление —
  в корзину; «открыт в Word» только при удачном открытии).
* Новые разделы: «Где хранятся данные», «Резервное копирование»,
  «Восстановление», «Установка и обновление», «Ограничения и известные
  проблемы», «Безопасность и приватность», «Схема database.json»,
  Troubleshooting/FAQ, раздел для разработчика.
* Этот CHANGELOG; версия синхронизирована в main.py, installer.iss и
  EWDochub.spec (VersionInfo exe).

### Архитектура (этап 9)
* `document_builder.py` — печатные формы (F, PH, замены, НДС) вынесены
  из main.py (п. 9.1).
* `services.py` — сервисный слой: валидация, кэш шаблонов, запись .docx,
  транзакция «файл → запись реестра» с откатом (п. 9.2); UI только
  собирает данные и показывает результат.
* `win_shell.py` — Win32-обвязка окна (п. 9.3); `widgets.py` — SpecTable
  (п. 9.4); `document_importer.py` использует единый источник имён полей
  F (п. 9.6); константы печатной формы спецификации (поставщик, город,
  год, ставка НДС, номер приложения) — в settings.json (п. 9.7).
* Расчёт НДС — единый для предпросмотра и печатной формы (п. 9.8).

### Зависимости
* `requirements.txt`: добавлены `openpyxl` (рантайм-зависимость импорта
  .xlsx) и `Pillow`; целевой Python — 3.13.

## 1.5.0 — 2026-11-18 (этапы 5–6 плана: P2 — производительность и поставка)
* Кэш шаблонов .docx, дебаунс предпросмотра спецификации, замена
  плейсхолдеров одним проходом (O(n²) → O(n)).
* Импорт: одно сохранение реестра на пакет, отмена загрузки.
* Реестр без полной перерисовки; комбобокс O(1) с лимитом 100 пунктов;
  ленивый первый рендер; метрики операций > 500 мс в журнале.
* Установщик: MinVersion/ArchitecturesAllowed/AppMutex/CloseApplications,
  страница лицензии, версия в имени установщика и в свойствах exe,
  деинсталлятор спрашивает про данные.
* Честные сообщения сохранения («сохранён» / «сохранён и открыт»), папка
  документов по умолчанию «Документы\EW.DocHub», работа с любым монитором
  (DPI/рабочая область), безопасные курсоры растяжения.

## 1.4.0 — 2026-11-18 (этапы 2–4 плана: P1 — надёжность и восстановление)
* Атомарная запись реестра с fsync, копиями `.bak` и повтором при сбое.
* Блокировка второго экземпляра; журнал без реквизитов; сверка
  «реестр ↔ папка документов» при старте.
* Корзина с восстановлением и автоочисткой через 30 дней; подтверждения
  удалений; санитизация путей; честное поведение с импортированными
  оригиналами.
* Качество импорта: расчётный счёт, название без «хвоста», без «полукопий»,
  лимиты и защита парсера, понятные причины отказа.
* UX-защиты: дубликаты, единый текущий контрагент, предпросмотр только
  для чтения, защита несохранённых данных, поиск по названию и ИНН,
  Ctrl+S, уведомление с «Открыть файл»/«Показать в папке».

## 1.3.1 — 2026-11-18 (этап 1 плана: P0 — остановить потерю данных)
* Печатная форма спецификации для ИП: отдельный шаблон (ОГРНИП вместо
  ОГРН, без КПП) — устранён единственный подтверждённый дефект форм.
* Allowlist импорта (.docx/.xlsx), лимиты размера и «архивных бомб».
* Ключ DaData больше не хранится в коде — только локально у пользователя.
* Защита чтения реестра: `.bad`-копия и предупреждение вместо молчаливой
  потери данных; проверка результата `save()`; порядок «файл → запись»;
  атомарная запись .docx и настроек; сохранение Mark-of-the-Web.
