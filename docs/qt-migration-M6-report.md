# EW.DocHub — отчёт этапа M6: договор, доп. соглашение, импорт, START-1, настройки

Ветка `qt-migration`, коммит **6d7e84f** (родитель — M5 `067def7`).
План: `DocHub_qt_migration_2.28.2_rev1.md`, раздел «M6 — Договор, доп.
соглашение, импорт, настройки, корзина, сверка (L)».
Среда разработки: Linux-песочница, Python 3.12.16, PySide6 6.12.0,
Xvfb :99 (Tk) / offscreen (Qt). Приёмка Windows — по runbook
`DocHub_M6_windows_runbook.md` (К-1…К-4, «не проверено» до прогона).
Этап выполнен подзадачами с отдельными коммитами по одному сценарию
(риск M6 «самый широкий этап» из плана).

---

## 1. Подзадачи этапа (по составу M6)

1. M6-a: страницы «Договор поставки» и «Доп. соглашение» с отложенными
   предпросмотрами; сохранение через `services.save_document`;
   «Действует до» (дефолт 31.12 текущего года) и теги сроков (2.18.0).
2. M6-b: импорт пакета целиком — guard, лимиты, фоновый воркер,
   «привязать/создать/пропустить», пакетная сводка U9, папка unknown,
   отчёт с «Открыть реестр» U10.
3. M6-c: стартовые дисковые задачи START-1 (QTimer-применение) —
   TRASH-WARN (сводка перед автоочисткой 30 дней), сверка/восстановление
   осиротевших файлов (DEF-3), уведомление о сроках доп. соглашений
   раз в сутки (2.18.0).
4. M6-d: страница «Настройки» — тема, папка документов, ключ DaData
   (DPAPI), копии реестра (BKUP-1), диагностика, горячие клавиши.
5. Кросс-этапные: защита несохранённых на всех четырёх страницах
   (спецификация, карточка, договор, доп. соглашение), LAZY-1, единый
   текущий контрагент на три страницы документов, smoke_qt «полный
   маршрут».

## 3. Что сделано

**Новые файлы**

- `document_page_qt.py` — ContractPageQt/AdditionalPageQt: отложенные
  предпросмотры (120 мс, только на видимой странице P-07), поиск по ИНН
  (U3), единый текущий контрагент, «Действует до» с дефолтом 31.12
  текущего года (п. 5 шаблона), сумма/срок прописью, лимит с разрядами и
  сохранением курсора; сохранение — транзакция сервисного слоя (п. 9.2,
  DEF-4 — честное сообщение), подтверждение повтора номера (п. 4.1),
  валидация с подсветкой полей.
- `import_qt.py` — ImportFlowQt: дословный перенос import_controller
  (guard, `_pack_problem`, воркер + опрос очереди QTimer, U9-сводка,
  `register_result`, batch save, unknown, отчёт U10); диалоги — QDialog.
- `startup_qt.py` — StartupFlowQt: read-only воркер (temp → trash_plan →
  orphans → notice), применение только в главном потоке, флаг остановки,
  perf-каналы `startup.*` те же.
- `settings_page_qt.py` — SettingsPageController: тема (радиопара через
  `app.set_theme`), папка документов с немедленным сохранением, ключ
  DaData (поле парольное, сохранённый ключ не подставляется — аудит
  2.0.1), копии BKUP-1, диагностика, горячие клавиши (U14).
- `tests/test_document_page_qt.py` — 31 тест;
  `tests/test_import_qt.py` — 27; `tests/test_startup_qt.py` — 20
  (включая пинг UI и LAZY-1); `tests/test_settings_page_qt.py` — 20.

**Изменённые**

- `main_qt.py` — «Договор», «Доп. соглашение», «Настройки» стали живыми
  страницами; `set_current_party` — fan-out по трём страницам документов
  с guard `_syncing_party` (п. 4.2); защита несохранённых для четырёх
  страниц (подписи Tk form_label); `save_setting` возвращает результат
  записи (Tk `_persist_settings`); стартовые задачи: `cleanup_expired_trash`
  (TRASH-WARN), `apply_expiry_notice` + суточный гейт, автокопия BKUP-1
  в прежней точке (singleShot 400 мс), остановка воркера при закрытии;
  `import_documents_dialog`/`import_drop_files` (нативный Qt drag&drop
  в MainWindow — Win32-хуки Tk не переносятся).
- `spec_page_qt.py` — `page_key`; перенос выбора контрагента на другие
  страницы через каркас (п. 4.2, симметрия с M6-страницами).
- `registry_page_qt.py` — кнопка «Добавить документы…» в шапке (точка
  входа импорта Tk-паритета); `scan_consistency`, баннер «файлов вне
  реестра» с кнопкой «Разобрать», `open_reconcile_dialog` (восстановить/
  в корзину, D1 — честные счётчики); `import os`, `reconcile`,
  `safe_filename`.
- `smoke_qt.py` — «полный маршрут» M6: 36 новых проверок (126 всего);
  диалог `choice` подменён до создания каркаса (стартовый диалог сроков
  не вешает прогон); воркер импорта — синхронная фабрика.
- `tests/test_main_qt.py`, `tests/test_spec_page_qt.py` — честное
  обновление списков живых страниц (все шесть разделов живы; «Обновления»
  — карточка M7 внутри настроек).
- `tests/test_registry_page_qt.py` — стабилизация прокрутки 10k
  (двухпроходная, деталь — раздел 6).
- `docs/qt-migration-stage-notes.md` — раздел M6.

## 6. Отклонения от Tk и решения этапа

1. **Единый текущий контрагент** — fan-out каркаса вместо Tk-синхронизации
   StringVar: семантика та же (выбор переносится, устаревший очищается),
   страница-источник пропускается, рекурсия исключена guard'ом.
2. **Drag&drop** — нативный Qt (MainWindow.dropEvent) вместо Win32-хуков
   WM_DROPFILES: точка входа та же (`import_flow.start`), К-3 (Win32)
   в Qt-сборке не задействован.
3. **Кнопка «Редактировать карточку»** на панели «Документ для»
   спецификации (M4) — оставлена, как решено в M5.
4. **Карточка «Обновления»** на странице настроек — не перенесена (M7
   по плану: UI обновлений с оркестрацией updater_controller). Это
   единственный блок Tk-страницы настроек, отсутствующий в Qt.
5. **Стабилизация 10k-теста** (6d7e84f): M6-кнопка в шапке реестра
   изменила высоту шапки — первая компоновка после смены фильтра
   сдвигает максимум скроллбара на один тик (offscreen: 9984 из 9985).
   Прокрутка в тесте сделана двухпроходной — равна поведению реальной
   прокрутки до конца списка; смысл проверки («скроллбар жив, прокрутка
   в конец не падает») сохранён, ослабления нет.
6. **Константы спецификации** — редактора нет в обеих сборках: значения
   задаются settings.json (`app_common.get_spec_settings`, M1); сценарий
   Г #16 закрыт остальными блоками настроек.

## 7. UX-наблюдения этапа (кратко; полностью — в stage-notes)

- Комбо контрагентов и предпросмотры в Qt — системные жесты; перенос
  выбора между страницами «переезжает» мгновенно (fan-out).
- Лимит с разрядами: курсор ставится синхронно (в Tk — after_idle-хак).
- Прогресс импорта — QDialog; Escape не закрывает (отмена — только
  кнопкой, как grab_set в Tk).
- Windows-проверка DPI 150%, drag&drop, модальности — runbook M6,
  «не проверено» до прогона.

## 8. Публикация

- Прямой `git push origin qt-migration` из песочницы невозможен
  (учётных данных git нет); API-плагин GitHub не переносит git-историю
  (снимок файлов создал бы divergent-SHA коммит — 34 файла, ~1 МБ).
- Сделано через плагин: на ветку `qt-migration` опубликована
  документация этапа — `docs/qt-migration-stage-notes.md` (раздел M6),
  `docs/qt-migration-M6-report.md`, `docs/qt-migration-M6-windows-runbook.md`
  — снимок-коммит поверх `9c829c3` (M2-эпоха).
- Каноническая история (11 коммитов M1–M6, включая 6 коммитов M6) — в
  bundle **DocHub-qt-migration-M6.bundle** (verify пройден). Публикация
  кода — на машине с bundle:
  `git clone DocHub-qt-migration-M6.bundle dochub-m6 && cd dochub-m6 && git push origin qt-migration`
  (origin получит настоящую историю; коммит документации от плагина
  перекроется — при желании сохранить его, сделать merge или
  force-with-lease).
