# EW.DocHub — отчёт этапа M8: публикация релиза и канал отката

Ветка `qt-migration`, релизная версия **2.29.0** (бамп с 2.28.2).
План: `DocHub_qt_migration_2.28.2_rev1.md`, раздел «M8 — Переключение
канала и откат (S–M)» и И.2/И.3. Вход — M7 (CP2): паритет подтверждён
на Linux (потерянных проверок = 0), Windows-критерии M7 остаются
«не проверено» до прогона по runbook M7.
Среда: Linux-песочница, Python 3.12.16, PySide6/Qt 6.12.0, Xvfb :99.

---

## 1. Подзадачи этапа (по составу M8)

1. **Версия релиза** — бамп 2.28.2 → 2.29.0 по И.2 (числовая
   `APP_VERSION`, флейвор суффиксом «-qt»), синхронно в `app_common.py`,
   `installer.iss`, `installer_qt.iss`, README — `tools/bump_version.py`.
2. **README/CHANGELOG обновляются** — сборка Qt как основная, раздел
   про самописные жесты рамки уходит (З.6), описание сборки обоих
   флейворов, карта файлов.
3. **Публикация кода миграции** — M3–M7 + релиз публикуются с машины
   пользователя из релизного bundle (шаг 0 runbook: пуш qt-migration
   и main — оба fast-forward). Tk-код из дерева НЕ удаляется (откат —
   сборкой, не археологией).
4. **Релиз** — код публикуется с машины пользователя из релизного bundle
   (см. `qt-migration-M8-windows-runbook.md`, шаг 0: пуш qt-migration и
   main — оба fast-forward; каноническая история 17 коммитов сохраняется);
   тег `v2.29.0` → `release.yml` собирает оба флейвора на Windows,
   pytest+smoke на Windows, SHA256SUMS.txt обоих ассетов, GitHub Release.
5. **Заморозка Tk-канала** — Tk остаётся на 2.28.2; критические фиксы
   Tk — только при инциденте данных (И.2).

## 3. Что сделано (Linux, релизная подготовка)

* **Версия**: `python tools/bump_version.py 2.29.0` — `app_common.py`
  (`APP_VERSION = "2.29.0"`), оба установщика (`MyAppVersion`), README
  (заголовок, имена setup.exe). Спец-файлы собственной копии версии не
  держат (проверка скрипта).
* **CHANGELOG.md** — запись 2.29.0: состав Qt-релиза, флейвор-канал,
  паритет/проверки Linux, раздел «Не проверено (Windows)» с
  runbook-ссылкой (замеры Е вносятся на прогонах — решение M7).
* **README.md** — интро (Qt с 2.29.0, Tk — откатная 2.28.2), виджет
  реестра (QTableView / ttk.Treeview), рамка окна: системная нативная,
  самописные жесты Tk ушли в заметку про откатную сборку (M8/З.6),
  установка (два установщика с одним AppId, обновление Tk→Qt поверх),
  сборка (оба флейвора, источник версии `app_common.py`), карта файлов
  (Qt-страницы, GUI-free ядра, smoke_qt, docs/).
* **Стабилизация теста стартового воркера** (`tests/test_startup_qt.py`,
  release-gate): дренаж фиксированными 2000 итераций без пауз под
  нагрузкой песочницы кончался раньше первого слайса GIL воркера —
  флак passed/failed/passed в повторах. Заменено дедлайном 15 с с
  паузой 2 мс; семантика проверок прежняя, продукт не менялся
  (воркер завершается за миллисекунды — проверено зондами). Прецедент —
  стабилизация 10k-реестра (коммит 6d7e84f, M6).
* **Публикация кода**: дельта M3–M7 + релиз (53 файла, ~1,5 МБ) НЕ
  публикуется из песочницы: плагин GitHub принимает содержимое файлов
  только inline — передача 1,5 МБ через контекст чревата искажениями,
  частичный пуш оставил бы несогласованное дерево (CI красный); git
  push без учётных данных невозможен. Канал — тот же, что согласован
  для M6: релизный bundle `DocHub-qt-migration-release-M8.bundle`,
  пуш с машины пользователя. Линия GitHub `qt-migration` (084b9b3 —
  M0–M2 + снимок M6-документации) и каноническая история расходятся
  (плагин создавал M0–M2 заново — другие SHA при том же контенте),
  поэтому вершина bundle — merge-коммит публикации (`-s ours`: дерево
  == дереву релизного коммита, проверено хешем; обе линии в предках —
  ничего не теряется, force не нужен): оба пуша (`qt-migration` и
  `qt-migration:main`) — fast-forward. Bundle проверен тестовым клоном.

## 5. Публикация релиза (шаги пользователя, ~10 минут + время CI)

1. **Пуш кода из bundle** (шаг 0 runbook): клонировать
   `DocHub-qt-migration-release-M8.bundle`, пуш `qt-migration`, затем
   `qt-migration:main` — оба fast-forward, история сохраняется целиком.
2. **Тег**: GitHub → Releases → Draft new release → тег `v2.29.0`
   на `main` (или `git tag v2.29.0 && git push gh v2.29.0`): пуш тега
   запускает `release.yml` (pytest + smoke обоих сборок на
   windows-latest, PyInstaller + Inno Setup, подпись при заданных
   секретах, `SHA256SUMS.txt` двух строк, GitHub Release с ассетами).
3. Проверить релиз: оба `*-setup.exe` + `SHA256SUMS.txt` (обе строки,
   суммы совпадают с файлами), заменить тело релиза текстом
   `docs/RELEASE_NOTES_v2.29.0.md`.
4. Дальше — runbook M8: установка/обновление Tk→Qt (К-5), замеры Е,
   откат (И.3), К-6 между релизами, К-8.

## 6. Итог этапа

**Сделано** — версия 2.29.0 (единый источник), CHANGELOG/README для
Qt-релиза, релизный коммит (17-й коммит канонической истории M3–M7),
release-gate стабилизация теста воркера, полная Linux-проверка
(1181/0/0, smoke 358/358 и 145/145), релизный bundle с проверкой
тестовым клоном, инструкция публикации (пуш из bundle → тег → CI →
ассеты).

**Не сделано** — передача кода на GitHub из песочницы (плагин принимает
содержимое только inline — 1,5 МБ через контекст не проходит без риска
искажения, частичный пуш ломает дерево; git push без учётных данных
невозможен) — выполняется пушем из bundle с машины пользователя, шаг 0
runbook; удаление Tk-слоя (по плану — только после решения о
переключении, отдельной задачей с переносом оставшихся Tk-тестов);
разморозка FEAT-1…FEAT-7 (отдельное решение после стабилизации).

**Не проверено (Windows, runbook M8)** — релизная сборка CI (тег),
К-5 (установка/обновление Tk 2.28.2 → Qt, SmartScreen, DPI 150 %),
К-6 (цепочка Qt→Qt между релизами), К-8 (сетевая папка), замеры Е с
внесением в CHANGELOG, откат на 2.28.2 (И.3).
