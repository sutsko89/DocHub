# EW.DocHub — runbook приёмки этапа M6 на Windows

Этап: M6 (договор, доп. соглашение, импорт, START-1/корзина/сверка,
настройки). Ветка `qt-migration`, коммит **6d7e84f** (полная история —
bundle `DocHub-qt-migration-M6.bundle`). Всё, что ниже, — шаги на реальной
Windows-машине; Linux-статус «выполнено» не заменяет этот прогон
(К-1…К-4, раздел К плана).

Подготовка (один раз):

```bat
git clone DocHub-qt-migration-M6.bundle dochub-m6
cd dochub-m6
git checkout qt-migration
py -3.13 -m pip install -r requirements.txt -r requirements-dev.txt
```

Требования: Python 3.13 (как у сборки 2.28.2), PySide6 >= 6.6.0,
Windows 10/11. Запуск тестов — из корня репозитория.

---

## 1. Полный pytest с финальной строкой `-rs`

```bat
py -3.13 -m pytest tests/ -rs
```

Ожидание (по Linux-прогону 6d7e84f): **1138 passed / 0 skipped /
0 failed**. Финальную строку (в т. ч. пустой раздел `-rs` — пропусков
нет) внести в протокол К. Если на Windows появляются пропуски/сбои
Windows-only-тестов (single instance, win_shell, сборка) — сравнить с
M0–M5: это те же suites, M6 их не менял.

## 2. Smoke обеих сборок

```bat
py -3.13 smoke_test.py
```

Ожидание: `SMOKE OK: 358 проверок` (Tk-сборка 2.28.2 — не сломана;
W-2 при штатном прогоне не проявляется).

```bat
py -3.13 smoke_qt.py
```

Ожидание: `SMOKE QT OK: 126 проверок`. Smoke_qt изолирует профиль
(%TEMP%\dogovor_smoke_qt_appdata), сеть отключает
(EWDOCHUB_NO_UPDATE_CHECK=1), perf-лог пишет startup.built/ready.
В разделе 15 (полный маршрут M6) на экране мелькают страницы и
подтверждения — это ожидаемо; модальные диалоги подменены.

## 3. К-4: DPI 150% и раскладка новых страниц (M6)

1. Параметры экрана → масштаб 150% → запустить `py -3.13 main_qt.py`.
2. Проверить поочерёдно все шесть разделов: шапки, карточки полей,
   предпросмотр договора/доп. соглашения, панель «Документ для»,
   страница настроек. Ожидание: читаемые шрифты, без обрезанных
   подписей, стандартная системная рамка (нативный заголовок и кнопки).
3. Перетащить окно на монитор с другим DPI — интерфейс остаётся
   соразмерным (Qt масштабирует нативно).
4. Проверить лимит доп. соглашения: ввод «1000000» → «1 000 000»,
   курсор не съедает ввод при вставке цифры в середину.

## 4. Перетаскивание файлов и модальность импорта (нативный Qt DnD)

1. Запустить `py -3.13 main_qt.py`, создать контрагента, сохранить
   договор (любые валидные реквизиты) — файл появится в
   «Документы\EW.DocHub\<Контрагент>\».
2. Перетащить в окно 2–3 файла .docx (можно из «Документов»):
   ожидание — открылось окно прогресса «Загрузка документов»,
   анализируется в фоне, окно программы отвечает.
3. Кнопка «Отменить» в прогрессе — остаток пакета не регистрируется,
   отчёт честно считает «Отменено пользователем: N».
4. Отчёт импорта: по каждому файлу тип/результат/причина;
   кнопка «Открыть реестр» открывает обновлённый реестр (U10).
5. Escape в окне прогресса НЕ закрывает его (отмена — только кнопкой).

## 5. U9: пакет без ИНН — 1–2 диалога вместо 20+

1. Подготовить папку с 20 .docx-договорами без ИНН (тип опознаваем:
   текст начинается «ДОГОВОР ПОСТАВКИ», есть название контрагента,
   ИНН отсутствует — «старые» файлы).
2. Импорт через «Добавить документы…» (кнопка в шапке реестра).
3. Ожидание: ОДИН диалог «Импорт: 20 файлов без ИНН» с перечнем
   названий и четырьмя вариантами (создать по названиям / привязать к
   выбранному / по каждому / пропустить); при «Создать по названиям» —
   одна карточка на одно название, дубли не плодятся; отчёт —
   «Добавлено документов: 20 (новых контрагентов: N)».
4. Повторить импорт того же пакета — отчёт: «уже были в реестре: 20»
   (дубликаты не добавляются).

## 6. START-1, TRASH-WARN, сверка (DEF-3)

1. Запуск приложения: в первые секунды в perf-журнале
   (`EWDOCHUB_PERF_LOG=1`) — каналы startup.temp/trash_count/orphans/
   notice (воркер) и startup.apply_* (главный поток); интерфейс
   отвечает в первые 5 секунд (критерий START-1).
2. Корзина: удалить документ → запись в секции «Корзина»; в базе
   (скриптом или руками) проставить deleted_at старше 31 дня →
   перезапуск → сводка «Автоочистка корзины: будет удалено 1 записей…»
   в app.log ДО удаления, после — тост «Автоочистка корзины: удалено
   1 записей…» и статус без «В корзине». Пустой план — тишина.
3. Сверка: положить в папку контрагента файл, которого нет в реестре
   (например, «Договор № 990 от июня.docx») → перезапуск → баннер
   «В папке документов найдено файлов вне реестра: 1» над списком
   реестра с кнопкой «Разобрать» → «Восстановить в реестр» → запись
   создана (тип и номер по имени файла), баннер исчез. Повторить с
   «В корзину» — файл уходит в `<папка документов>\_trash\<дата-время>`.
4. Сроки доп. соглашений: сохранить доп. соглашение с «Действует до»
   в прошлом → перезапуск → диалог «Сроки действия доп. соглашений»
   с «Открыть реестр»/«Позже»; повторный запуск в тот же день — тишина
   (суточный гейт, ключ last_expiry_notice в settings.json).

## 7. Ключ DaData: DPAPI (К-2 сопутствующее)

1. Настройки → DaData → ввести ключ → «Сохранить ключ» → ожидание:
   алерт «Ключ сохранён… Значение зашифровано (DPAPI)», статус
   «Ключ сохранён и зашифрован (DPAPI, профиль пользователя)».
2. Поле остаётся пустым; повторный вход на страницу — ключ не
   подставляется, статус не раскрывает значение.
3. «Удалить ключ» → подтверждение (Enter = «Отмена», U7) → статус
   «Ключ не задан».
4. Сравнить с Tk-сборкой 2.28.2: ключ, сохранённый Qt-сборкой, читается
   Tk-сборкой (тот же профиль и формат хранилища).

## 8. Защита несохранённых на четырёх страницах

1. Ввести данные в договор (номер), уйти со страницы → подтверждение
   «На странице «Договор поставки» есть несохранённые данные» (Enter
   по умолчанию — «Остаться», U7). Повторить для доп. соглашения,
   спецификации, карточки.
2. Закрыть окно с «грязной» формой каждой страницы — подпись страницы
   в диалоге соответствует разделу; отказ — окно остаётся открытым.
3. Ctrl+S на каждой странице сохраняет именно её форму.
4. Сбой чтения подписи (искусственно не воспроизводится на Windows) —
   считается «грязной» (тесты offscreen).

## 9. LAZY-1 на реальной базе

1. Сохранить 2–3 документа, закрыть программу, открыть снова (тела
   ленивые).
2. Реестр → выделить договор → «Открыть Word» → сохранённый .docx
   содержит полные реквизиты (тело дочитано store.document_body).
3. Доп. соглашение: выбрать ленивый договор-основание → предпросмотр
   полный; сохранить — в extra полные данные.

## 10. Что фиксировать в протоколе К

- Версии: Python, PySide6, Windows; коммит 6d7e84f.
- Финальная строка pytest `-rs` (полный прогон) — Tk и Qt раздельно.
- smoke_test.py и smoke_qt.py — счётчики и код возврата.
- DPI 150%: скриншоты шапок страниц договора/доп. соглашения/настроек.
- Drag&drop: скриншот прогресса и отчёта импорта.
- TRASH-WARN: строки app.log (сводка ДО удаления, итог).
- Сверка: скриншот баннера сирот и диалога разбора.
- Замечания — отдельным списком «старое/новое» (W-1/W-2 заморожены).
