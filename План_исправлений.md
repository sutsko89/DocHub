## Этап 0. Подготовка (до правок)

## Этап 2. P1 — надёжность и восстановление (1.4)

### 2.1. Укрепить запись реестра
- `fsync` файла перед `os.replace`; уникальное имя `database.json.<pid>.tmp`.
- `database.json.bak` (хранить 3–5 версий) перед заменой; поле `"schema_version": 2`.
- Повтор записи 2–3 раза с паузой при временных `OSError` (антивирус/сканер).
- **Приёмка:** тест с имитацией сбоя между `write` и `replace` не теряет предыдущую версию.

### 2.2. Блокировка второго экземпляра
- Named mutex (Win32) или lock-файл в `%APPDATA%\DogovorGenerator`; при занятом — сообщение «программа уже запущена» и активация существующего окна (по возможности).
- **Приёмка:** два запуска не пишут в один `database.json`.

### 2.3. Логирование с редактированием
- Модуль `logging`, файл `%APPDATA%\DogovorGenerator\logs\app.log`, ротация (1–5 МБ × 3).
- Писать: старт/версию, ошибки load/save/copy/open, длительность операций > 500 мс.
- **Не писать**: значения полей `F`, ИНН, счета, ключ, полный текст документов, полные пути (только `id`, тип, размер, результат).
- Заменить молчаливые `except ...: pass` в критичных местах (удаление файлов, save) на логирование.
- **Приёмка:** по логу можно диагностировать сбой, и в нём нет реквизитов (проверить grep по тестовым данным).

### 2.4. Сверка «реестр ↔ папка документов» при старте
- Сканировать `<папка документов>/*/` и `unknown/`, сопоставлять с реестром.
- Показывать отчёт: «найдено N файлов вне реестра» → «восстановить в реестр / переместить в корзину / оставить».
- **Приёмка:** удаление `database.json` при целых файлах позволяет восстановить реестр без ручного выбора каждого файла.

### 2.5. Безопасное удаление и подтверждения
- [`_delete_document()`](main.py:3287) — подтверждение с типом, номером, датой, контрагентом и строкой «файл на диске останется»; разнести «Удалить» и «Открыть».
- Удаление контрагента — перечень документов (тип/номер/дата), явно «файлы останутся в папке …», красная кнопка подтверждения; для большого числа — второе подтверждение.
- Решить и реализовать политику файлов: либо удалять физически с подтверждением, либо честно сообщать.
- **Приёмка:** ни одно удаление не происходит без явного подтверждения с описанием последствий.

### 2.6. Корзина / отмена удаления
- Мягкое удаление: флаг `deleted_at` в записи + раздел «Корзина», восстановление; физическая очистка по кнопке/таймеру.
- **Приёмка:** удалённый документ восстанавливается из корзины.

### 2.7. Санитизация путей
- [`safe_filename()`](main.py:1001): запретить `.`/`..`, зарезервированные имена (`CON`, `PRN`, `NUL`, `COM1`…), точки/пробелы на конце; ограничить ~80 символами + короткий хэш.
- [`_party_documents_dir()`](main.py:2832): проверять итоговую длину пути (< 260 с запасом), не выходить за пределы каталога документов.
- **Приёмка:** контрагент `..` и очень длинное имя не создают файлов вне папки документов.

### 2.8. Не подменять папку молча
- [`_documents_dir()`](main.py:2816) / [`_party_documents_dir()`](main.py:2842): при `OSError` — алерт «папка недоступна» с выбором «повторить / выбрать другую / использовать по умолчанию».
- **Приёмка:** пользователь всегда знает, куда реально сохранён файл.

### 2.9. Честное поведение с импортированными оригиналами
- [`export_document()`](main.py:3251): если `extra.source_file` отсутствует — алерт «оригинал не найден» с выбором «открыть папку / пересобрать из шаблона (может быть неточным)», а не тихая генерация суррогата.
- **Приёмка:** нет «опасной подмены» документа без предупреждения.

- **Приёмка:** на 5 образцах из [`образцы/`](образцы/) расчётный счёт извлекается.

### 3.2. Название контрагента без «хвоста»
- [`document_importer.py:171–177`](document_importer.py:171): обрезать по маркерам «, именуемый», «, именуемое», «, в лице», «(далее — …)», кавычки/переносы; нормализовать `ООО "X"` → `ООО «X»`.
- **Приёмка:** на образце доп. соглашения в карточку попадает `ООО "ЛИДЕР ДВ"`, а не фраза с «именуемый в дальнейшем».

### 3.3. Не создавать «полукопии»
- Ввести критерий `recognized`: минимум ИНН + (название или КПП/ОГРН) для юрлица; для ИП — ИНН + ФИО.
- Если ИНН пуст — не создавать карточку автоматически: показать диалог «выберите существующего / создайте карточку / пропустить».
- При совпадении ИНН с существующим — привязывать документ к нему, а не создавать новую карточку.
- **Приёмка:** повторный импорт того же файла не плодит карточки.

### 3.4. Лимиты и защита парсера
- Максимальный размер файла (например, 50 МБ), количество файлов за пакет, суммарный объём, проверка свободного места.
- Защита от zip bomb: до распаковки проверять число членов и суммарный размер в ZIP.
- `defusedxml`/`resolve_entities=False` для XML — проверить и закрыть XXE.
- `TEXT_KEEP_LIMIT` применять до сохранения (и рассмотреть отказ от хранения полного текста — см. 4.1).
- **Приёмка:** «архивная бомба» и файл 500 МБ не вешают приложение.

### 3.5. Понятные причины отказа
- В отчёте импорта показывать по каждому файлу: тип, результат, **причину** отказа (нет текста, битый ZIP, неподдерживаемое расширение).
- **Приёмка:** пользователь понимает, почему файл не распознан.

## Этап 5. P2 — производительность (1.5)

Порядок — по соотношению «эффект / трудозатраты».

1. **Кэш шаблонов** `Document` в памяти (2 ч) — убирает чтение `.docx` на каждый предпросмотр.
2. **Дебаунс `_regenerate_spec()`** (2 ч) + обновление только итогов.
3. **Один проход в `replace_in_paragraph()`** вместо O(n²) `rebuild_full_text` (2 ч).
4. **Реестр: частичное обновление** вместо полной перерисовки (1–2 д): обновлять строку/секцию, раскрытие документов и поиск не пересоздают всех контрагентов; далее — виртуализация/страницы по 50–100.
5. **Батчинг записи JSON** (1 д): debounce 300–500 мс в фоновом потоке; один `save()` на пакет импорта; транзакция в `_finish_documents_import`.
6. **Регистрация импорта — в фон** с прогрессом, отменой и одним сохранением (1 д).
7. **Комбобокс** (1 д): не создавать `tk.Label` на каждый пункт (лимит 100 + поиск/скролл), убрать O(n) перекраску в `_set_index()`.
8. **Таблица спецификации** (1 д): виртуализация/`Treeview`, ограничение числа строк, не создавать 500 строк виджетов одним вызовом.
9. **Ленивая сборка страниц** (0,5 д) — ускоряет старт и снижает память.
10. **Метрики**: логировать операции > 500 мс; тест производительности на 100/1000/5000.
11. **Стратегически — SQLite (WAL, индексы по ИНН/`party_id`)** вместо JSON: решает и атомарность, и конкурентный доступ, и скорость. Требует миграции — планировать отдельным релизом.
12. **Не хранить полный текст импортированных документов** в реестре (главный драйвер размера) — хранить извлечённые поля + короткий фрагмент.

**Приёмка этапа:** сохранение и действия с реестром на 600 контрагентах — < 1 с; импорт 200 файлов — с прогрессом и без «зависания».
