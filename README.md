# EW.DocHub

Настольное приложение на Python для работы с контрагентами и документами:
договоры поставки, доп. соглашения и спецификации формируются из шаблонов
`.docx` по реквизитам контрагента. Реестр контрагентов и созданных документов
хранится локально, интерфейс оформлен в стиле macOS, тема — светлая и тёмная.

## Возможности

* **Карточка контрагента** — юр. лицо или ИП: коды (ИНН, КПП, ОГРН/ОГРНИП),
  названия, руководитель, адреса, контакты и банковские реквизиты.
  Автозаполнение по ИНН через сервис DaData.
* **Редактирование контрагента** — кнопка «Редактировать» в реестре открывает
  окно с полями карточки и кнопками «Сохранить»/«Отмена». Изменяется только
  карточка: **ранее созданные документы остаются без изменений**, так как
  каждый документ хранит собственную копию реквизитов на момент создания.
* **Договор поставки, доп. соглашение, спецификация** — печатная форма
  собирается напрямую из шаблона `.docx`, форматирование не «плывёт».
  Готовый файл сохраняется в папку контрагента и сразу открывается в Word.
* **Реестр** — список контрагентов с поиском по ИНН; по выбранному контрагенту
  видны все его документы. Контрагента можно отредактировать или удалить
  (вместе с его документами).
* **Добавить документы** — загрузка готовых `.docx`/`.xlsx`: программа в фоне
  определяет тип документа и контрагента (поиск по ИНН, иначе создание новой
  карточки) и добавляет их в реестр. Неопознанные файлы попадают в папку
  `unknown` и показываются в реестре отдельным разделом.
* **Настройки** — тема оформления (светлая/тёмная), папка для сохранения
  документов, кнопки «Выбрать папку…», «Открыть папку» и «Добавить документы…».

## Установка

Запустите `installer\EW.DocHub-<версия>-setup.exe` — установщик ставит EW.DocHub
в Program Files (или «только для меня» — по выбору), создаёт ярлык в меню
«Пуск» и (по выбору) на рабочем столе. Установка работает на Windows 10/11 x64;
если программа запущена, установщик предложит её закрыть. Удаление — через
«Панель управления → Программы»: деинсталлятор спросит, удалить ли настройки,
реестр, журнал и ключ DaData.

Данные хранятся в двух местах:

* **Документы** — по умолчанию в видимой папке «Документы\EW.DocHub»
  (с версии 1.5.0; ранее — скрытый %APPDATA%). Папку можно изменить в настройках.
* **Настройки и реестр** — в профиле пользователя: `%APPDATA%\DogovorGenerator`
  (`database.json` — реестр, `settings.json` — настройки, `logs\` — журнал,
  `dadata_key.txt` — ключ DaData).

## Запуск из исходников

```powershell
python -m pip install -r requirements.txt
python main.py
```

## Проверка

Быстрый тест логики и интерфейса без ручного кликанья — работает и на Windows,
и на Linux/macOS (для интерфейса нужен дисплей или Xvfb):

```powershell
python smoke_test.py
```

## Сборка и установщик

Сборка делается в два шага (требуются PyInstaller и Inno Setup):

```powershell
python -m pip install pyinstaller

# 1. Папочная сборка приложения (быстрый запуск, ничего не распаковывается)
pyinstaller --noconfirm EWDochub.spec

# 2. Установщик «EW.DocHub-<версия>-setup.exe» с ярлыками
#    (Inno Setup: https://jrsoftware.org/isinfo.php)
& "C:\Program Files\Inno Setup 7\ISCC.exe" installer.iss
```

Результаты:

* `dist\EW.DocHub\` — папочная сборка: `EW.DocHub.exe` стартует почти мгновенно;
* `installer\EW.DocHub-<версия>-setup.exe` — установщик: ставит приложение,
  создаёт ярлыки, показывает лицензию и уведомления о сторонних библиотеках.

Версия указана в свойствах `EW.DocHub.exe` (VersionInfo) и в имени файла
установщика. Подписание кодом (code signing) выполняется при наличии
сертификата — организационный шаг вне репозитория.

Спецификация сборки сама подтягивает данные `customtkinter` (темы, шрифты),
включает шаблоны документов и `app_icon.ico`, поэтому отдельно ничего
копировать не нужно.

## Как устроен интерфейс

* Своя рамка окна: скруглённые углы (DWM), «светофор» справа в шапке,
  перетаскивание за шапку, двойной клик по шапке — развернуть/восстановить.
* Меню **«Файл»** в левом верхнем углу открывает все разделы:
  «Добавить контрагента», «Договор поставки», «Доп. соглашение»,
  «Спецификация», «Реестр» (также работают `Ctrl+N` и кнопка в боковом меню).
* **Первый запуск**: если контрагентов ещё нет, окно «Добавить контрагента»
  открывается автоматически. Выбирается «Юр. лицо» или «ИП», заполняются коды
  (ИНН с автозаполнением по DaData), организация, руководитель, адреса,
  контакты и банковские реквизиты; кнопка «Сохранить контрагента» заносит
  карточку в реестр.
* Четыре страницы в боковом меню: **Договор поставки**, **Доп. соглашение**,
  **Спецификация**, **Реестр**. Настройки и импорт документов — в меню
  **«Настройки»**.
* Все поля проверяются на лету: ИНН/КПП/ОГРН/БИК/счета — по числу цифр,
  email и телефон — по формату; ошибки подсвечиваются прямо под полем.

## Папки документов и загрузка готовых файлов

* Все документы реестра сохраняются в **индивидуальную папку контрагента**:
  `<папка документов>/<контрагент>/` (например, `Документы/ООО ЛИДЕР ДВ/`).
  Общая папка выбирается в настройках, для каждого контрагента программа
  заводит свою.
* Кнопка **«Добавить документы…»** в настройках: выберите готовые договоры,
  доп. соглашения и спецификации (`.docx`, `.xlsx`) — программа в фоновом
  режиме определит тип документа и контрагента (поиск по ИНН, иначе создание
  новой карточки), добавит записи в реестр и скопирует файлы в папку
  контрагента. Пользователю показывается только экран загрузки.
* Файлы, которые не удалось опознать, копируются в папку
  `<папка документов>/unknown` и показываются в реестре в разделе
  «Неопознанные документы».

## Надёжность и защита данных (с версии 1.4.0)

* **Блокировка второго экземпляра.** Одновременно может работать только одна
  копия программы: две копии писали бы в один файл реестра и теряли данные.
  Повторный запуск показывает подсказку и активирует уже открытое окно.
* **Атомарная запись реестра.** `database.json` пишется через временный файл
  с контролем записи; предыдущие версии хранятся как `database.json.bak`,
  `.bak.1` … `.bak.4`. Сбой записи повторяется автоматически (антивирус или
  сканер временно занял файл — данные всё равно сохраняются).
* **Корзина.** Удаление контрагента и документа переносит записи в корзину,
  файлы на диске остаются. Восстановление — из раздела «Корзина»; записи
  старше 30 дней удаляются автоматически.
* **Подтверждения.** Ни одно удаление не выполняется без явного подтверждения
  с описанием последствий (тип, номер, контрагент, судьба файлов на диске).
* **Сверка реестра и папки документов.** При старте программа находит файлы,
  которых нет в реестре, и предлагает восстановить записи — реестр можно
  поднять из папки документов, если `database.json` был утерян.
* **Защита импорта.** Файлы больше 50 МБ, «архивные бомбы» и архивы с
  избыточным числом частей отклоняются до разбора; пакет импорта ограничен
  по числу файлов и суммарному объёму. Причины отказа видны в отчёте.
* **Дубликаты.** Карточка с уже существующим ИНН создаётся только после
  явного выбора («открыть существующего / создать всё равно»); повтор номера
  документа у контрагента требует подтверждения.
* **Несохранённые данные.** Изменённые формы не теряются молча: при закрытии
  программы или уходе со страницы запрашивается подтверждение.
* **Журнал без реквизитов.** Технический лог (`logs/app.log` в профиле
  пользователя) фиксирует старт, ошибки и длительные операции. Реквизиты
  (ИНН, счета, ФИО), названия и тексты документов в лог не попадают.

## Производительность (с версии 1.5.0)

* **Шаблоны кэшируются.** Предпросмотр больше не читает и не разбирает ZIP
  шаблона при каждом нажатии — шаблон разбирается один раз, рендер получает
  копию из памяти; правка шаблона подхватывается автоматически.
* **Предпросмотр спецификации — с задержкой.** Как у договора и доп. соглашения,
  пересборка откладывается на 120 мс, а не идёт на каждый символ в поле.
* **Замена плейсхолдеров — одним проходом.** Убрана пересборка всего текста
  параграфа после каждой замены (O(n²) → O(n) на больших шаблонах).
* **Импорт пишет реестр одним сохранением.** Пакет из 200 файлов раньше делал
  200 полных перезаписей JSON с fsync — теперь одна запись на пакет;
  загрузку можно отменить кнопкой «Отменить».
* **Реестр не перерисовывается целиком.** Клик по контрагенту обновляет только
  подсветку и секцию его документов; при старте список рисуется лениво,
  при первом открытии страницы.
* **Комбобокс и таблица позиций.** В выпадающих списках — не больше 100 пунктов
  с подсказкой (дальше — поиск по ИНН), подсветка строки переставляется за O(1);
  задание 500 строк таблицы больше не тормозит интерфейс.
* **Метрики в журнале.** Запись/чтение реестра, разбор импорта и перерисовка
  реестра дольше 500 мс фиксируются в журнале — видно, что именно тормозит.
* Проверка производительности входит в `smoke_test.py`: 600 контрагентов
  записываются и читаются за секунды, 500 строк таблицы создаются без
  квадратичного замедления.
