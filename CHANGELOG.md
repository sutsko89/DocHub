# История версий EW.DocHub

Все изменения описаны относительно пунктов «Плана_исправлений.md».

## 2.1.0 — 2026-11-19 (исправления по комплексному аудиту)

Закрыты все находки P0 и выполнимая кодом часть P1 из аудита версии 2.0.1
(54 находки: 7 P1, 18 P2, 29 P3); refactoring ContractApp (P2) — отдельно,
после стабилизации 2.1.x.

### Корректность (P0)
* **Re-entry пакетного импорта (P1-1).** Guard `_import_running` перенесён
  из диалога в `_start_documents_import`: drag-and-drop больше не запускает
  второй импорт поверх работающего (раньше это смешивало отчёт и могло
  задваивать записи). Очередь результатов у каждого запуска своя и передаётся
  воркеру через `args`. Smoke-регрессия.
* **DaData без root.after() из потока (P1-3, P2-3).** Результат запроса идёт
  через `queue.Queue` и опрашивается из главного потока (`_cp_result_tick`)
  — тот же паттерн, что у импорта. Повторные клики «Заполнить по ИНН» при
  активном запросе игнорируются (guard `_cp_busy`) — раньше два воркера
  гонялись за одними полями формы.
* **Валидаторы ячеек SpecTable включены (P2-6).** `validate="key"` для
  «Кол-во»/«Цена» (раньше Tk создавал validatecommand, но никогда его не
  вызывал); вставка из буфера (`var.set`) проходит санитизацию — буквы в
  числовые ячейки больше не попадают.
* **Ошибки сбора форм не глотаются (P1-3, P2-9).** `_cp_collect` при сбое
  чтения поля возвращает `None` и логирует тип исключения (раньше сбойное
  поле молча обнулялось, и валидация честно ругалась на заполненное поле);
  `_cp_save` сообщает пользователю и не пишет реестр; `_form_signature`
  деградирует до `None` — страница считается «грязной», несохранённые
  данные защищены подтверждением, а не «тихой чистотой».
* **Версии синхронизированы (P2-16/17/18).** `EWDochub.spec` читает
  `APP_VERSION` из main.py (filevers/prodvers вычисляются из неё; блок
  VersionInfo — только на Windows-сборке), `installer.iss` синхронизируется
  скриптом `tools/bump_version.py`; несуществующее «О программе» из README
  убрано, заявка «работает на 3.10+» снята.
* **Чистка мусора (P2-4, P3).** Удалён монкипатч 18 атрибутов класса F в
  импортере (единый источник имён — document_builder; закреплено
  smoke-проверкой `di.F is m.F`); убраны мёртвые импорты (calendar, hashlib,
  zipfile, InvalidOperation, tkfont); pyinstaller добавлен в
  requirements-dev (команда сборки из README больше не падает на чистой
  машине).

### Безопасность
* **Ключ DaData шифруется DPAPI (P2-1).** На Windows файл ключа пишется
  через CryptProtectData (CurrentUser), старый открытый файл мигрирует при
  первом чтении, битый контейнер не роняет программу. В настройках ключ
  больше не подставляется в поле (маска + строка статуса) — реальное
  значение не видно и не копируется. Сбой шифрования деградирует к
  открытому тексту, не теряя ключ.
* **Мьютекс: Global\ + SID (P2-2).** `Global\EWDocHub_SingleInstance_<SID>`
  защищает и от второй сессии того же пользователя (консоль + RDP), у разных
  пользователей блокировки независимы; `WinDLL(use_last_error=True)` +
  `ctypes.get_last_error()` вместо ненадёжного GetLastError; при отказе в
  доступе к Global\ — деградация на Local\ с тем же именем. Для
  инсталлятора — фиксированный `Global\EWDocHub_InstallerMutex` (AppMutex
  в installer.iss обновлён).
* **TLS-ошибки DaData видны отдельно (P3).** SSLCertVerificationError больше
  не маскируется под «нет интернета» — отдельная ветка с понятным сообщением.
* **Дисклеймер DaData** в настройках и license.txt: при автозаполнении
  отправляется только ИНН (публичный идентификатор).

### Надёжность данных
* `.bad-*` копии повреждённого реестра чистятся по возрасту (30 дней)
  при запуске — раньше копились без ограничения (P3).
* fsync у `.bak`-копии при ротации: вторая линия обороны переживает сбой
  питания (P3).
* Год спецификации берётся на момент вызова `get_spec_settings()`, а не
  импорта модуля — приложение, пережившее Новый год в запущенном виде,
  больше не ставит в спецификации прошлый год (P3).

### Тесты и CI
* pytest: 113 → 153 теста. Новые: DPAPI-формат/миграция/битый контейнер,
  TLS-ветки DaData, валидаторы и санитизация SpecTable, сбор данных форм с
  фейковыми виджетами (старт покрытия main.py), уборка .bad-копий, fsync
  бэкапа, имена мьютексов + referенс installer.iss, XXE-гарантия парсера
  python-docx. Read-only тест переписан платформонезависимо — Windows
  выполняет полный набор без skip.
* smoke: 280 → 306 проверок. `check()` копит неудачи и печатает сводку в
  конце (код возврата — числу неудач; раньше процесс умирал на первой
  ошибке). Новые регрессии: re-entry импорта, guard повторных кликов
  DaData, validate="key" в таблице, DPAPI-формат ключа, уборка .bad,
  согласованность версий во всех файлах, Global-мьютекс.
* CI: Windows-джоба запускает GUI-smoke в графической сессии (аудит P1:
  целевая платформа обязана проверять GUI-инварианты до релиза); таймауты
  заданий, pip-кэш, concurrency-группа.
* Новый release-workflow (`.github/workflows/release.yml`): по тегу `v*`
  или вручную — pytest + smoke + PyInstaller + Inno Setup + SHA-256
  установщика в артефактах. Подпись сертификатом — организационный шаг
  (инструкции в шапке installer.iss).

## 2.0.1 — 2026-11-19 (исправление)

* **Поиск по ИНН в карточке ИП.** Переключатель «Юр. лицо / ИП» не был привязан
  к переменной типа карточки (`ui.segmented` не передавала `variable` в
  `CTkSegmentedButton`), поэтому `_cp_type_var` всегда оставалась «Юр. лицо».
  «Заполнить по ИНН» у ИП читала пустое скрытое поле юрлица и требовала
  «10 цифр» — поиск не срабатывал; той же причиной сломалось бы и сохранение
  карточки ИП. Теперь переменная привязана к сегменту, режим определяется
  корректно для обоих типов. Исправление в `ui_macos.py::segmented` и
  `main.py::_build_counterparty_page`.
* Smoke-тест дополнен регрессионной проверкой: реальный клик по сегменту «ИП»,
  «Заполнить по ИНН» с подменённым DaData и контроль подстановки реквизитов
  ЕГРИП (ФИО, ОГРНИП, адрес) в поля карточки ИП.

## 2.0.0 — 2026-11-18 (этапы 7–9 плана: P3)

### Тесты (этап 7)
* pytest-набор `tests/` — 113 теста без интерфейса: golden-сверка шести
  печатных форм с эталонами (проверка отсутствия `{{...}}` — регрессия бага
  1.1), проверка диска после сохранения, восстановление реестра (битый/
  обрезанный/null-JSON, дубли id, `.tmp`, `.bad`, read-only папка, сироты),
  импорт на образцах `.docx`/`.xlsx` (ООО и ИП, дубликаты ИНН, `.doc`,
  битые файлы), DaData с моком `urlopen` (200/401/429/500/URLError/таймаут),
  `safe_filename` и безопасность путей, негативная логика.
* Golden-эталоны: `tests/golden/*.json`, перегенерация —
  `python tests/make_golden.py`.
* Покрытие (цель ≥ 70 %): `document_builder` 93 %, `services` 80 %,
  `document_importer` 80 %, `storage` 80 %.
* CI на GitHub Actions (Python 3.13): Linux — pytest + smoke под Xvfb,
  Windows — pytest. `requirements-dev.txt`.
* **Исправление, найденное тестами:** в импортере после написания
  «Индивидуальный предприниматель» отсутствовал разделитель в регулярке —
  ФИО ИП не извлекалось и карточка не создавалась автоматически.

### Документация (этап 8)
* README переработан: интерфейс соответствует фактическому (кнопки в шапке
  вместо «меню Файл» и бокового меню; поиск по названию и ИНН; удаление —
  в корзину; «открыт в Word» только при удачном открытии).
* Новые разделы: «Где хранятся данные», «Резервное копирование»,
  «Восстановление», «Установка и обновление», «Ограничения и известные
  проблемы», «Безопасность и приватность», «Схема database.json»,
  Troubleshooting/FAQ, раздел для разработчика.
* Этот CHANGELOG; версия синхронизирована в main.py, installer.iss и
  EWDochub.spec (VersionInfo exe).

### Архитектура (этап 9)
* `document_builder.py` — печатные формы (F, PH, замены, НДС) вынесены
  из main.py (п. 9.1).
* `services.py` — сервисный слой: валидация, кэш шаблонов, запись .docx,
  транзакция «файл → запись реестра» с откатом (п. 9.2); UI только
  собирает данные и показывает результат.
* `win_shell.py` — Win32-обвязка окна (п. 9.3); `widgets.py` — SpecTable
  (п. 9.4); `document_importer.py` использует единый источник имён полей
  F (п. 9.6); константы печатной формы спецификации (поставщик, город,
  год, ставка НДС, номер приложения) — в settings.json (п. 9.7).
* Расчёт НДС — единый для предпросмотра и печатной формы (п. 9.8).

### Зависимости
* `requirements.txt`: добавлены `openpyxl` (рантайм-зависимость импорта
  .xlsx) и `Pillow`; целевой Python — 3.13.

## 1.5.0 — 2026-11-18 (этапы 5–6 плана: P2 — производительность и поставка)
* Кэш шаблонов .docx, дебаунс предпросмотра спецификации, замена
  плейсхолдеров одним проходом (O(n²) → O(n)).
* Импорт: одно сохранение реестра на пакет, отмена загрузки.
* Реестр без полной перерисовки; комбобокс O(1) с лимитом 100 пунктов;
  ленивый первый рендер; метрики операций > 500 мс в журнале.
* Установщик: MinVersion/ArchitecturesAllowed/AppMutex/CloseApplications,
  страница лицензии, версия в имени установщика и в свойствах exe,
  деинсталлятор спрашивает про данные.
* Честные сообщения сохранения («сохранён» / «сохранён и открыт»), папка
  документов по умолчанию «Документы\EW.DocHub», работа с любым монитором
  (DPI/рабочая область), безопасные курсоры растяжения.

## 1.4.0 — 2026-11-18 (этапы 2–4 плана: P1 — надёжность и восстановление)
* Атомарная запись реестра с fsync, копиями `.bak` и повтором при сбое.
