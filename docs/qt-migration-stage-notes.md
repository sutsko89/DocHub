# Заметки к этапам миграции Tk → PySide6 (бегущий журнал наблюдений)

Назначение: фиксация наблюдений, принятых решений и отложенных вопросов
этапов миграции по плану `DocHub_qt_migration_2.28.2_rev1.md`. Файл
живёт вместе с веткой `qt-migration` и дополняется по ходу этапов; всё,
что требует Windows-прогона, помечается «не проверено» и дублируется в
раздел К плана.

---

## Запись M1: приёмка по Windows (2026-11-23/24)

- Среда: Windows 11 (сборка 10.0.26300), Python 3.13.7, два монитора
  1920×1080. Регресс и smoke M1 (ad084ae) выполнены пользователем;
  EXE и установщик собираются, версия 2.28.2 подтверждена в свойствах
  EXE и на странице «Настройки» Tk-сборки. **M1 принят.**
- Установка установщика на чистой машине — **не проверено**
  (переносится: контроль установки выполнялся ранее по runbook M1,
  полный чистый прогон — на CP2/M7 вместе с Qt-установщиком).

### W-1 — плавающие ошибки Tk в pytest + 19 пропущенных test_tk_page_build

- Симптом: в `tests/test_registry_tree.py` и соседних Tk-фикстурах —
  плавающий `TclError` при создании `tk.Tk()`; на M1-коммите ошибка
  чаще, чем на пине 52d96eb (по наблюдениям пользователя), вне pytest
  Tk создаётся стабильно; плюс 19 пропусков `test_tk_page_build`.
- Воспроизводится на 52d96eb (до M1) → **причина не установлена,
  с M1 не связана** (решение пользователя от 2026-11-24).
- Статус (решение пользователя от 2026-11-24, обновлено): **не чиним
  и не маскируем; починка отложена до завершения миграции** — время на
  неё в этапах M2–M8 не тратится. Новых skip/ретраев ради зелёного
  результата не добавляется. Диагноз — после завершения миграции
  (предложение — в анализе фикстуры root, диалог 2026-11-24,
  применение — только по явному решению).

### W-2 — два FAIL smoke (проверки snap), 356/358

- Симптом: две проверки прилипания Tk-сборки падают в smoke на Windows;
  воспроизводится на 52d96eb; ручная проверка прилипания — работает.
- Статус (решение пользователя от 2026-11-24, обновлено): **не чиним
  и не маскируем; починка отложена до завершения миграции**; причина
  не установлена. Критерии snap-геометрии Tk с уводом Tk-слоя (M8)
  станут неактуальны; до этого — наблюдаем.

### Правила наблюдений на Windows (действуют с 2026-11-24)

1. Новых skip и ретраев не добавлять (в том числе в Qt-тестах) —
   счётчики пропусков в отчётах остаются честными и объяснёнными.
2. Каждый отчёт этапа содержит итоговую строку pytest со счётчиками
   и причинами пропусков (`-rs`), отдельно для Linux (offscreen/Xvfb)
   и для Windows.
3. Правило остановки: если на Windows появляется **новая**
   нестабильность в Qt-тестах (ошибки создания окна, загрузки
   плагинов и т. п.) — работа останавливается, пользователь получает
   доклад с логами как есть (без пересборок «до зелёного»); это
   дополняет правило остановки протокола Е §9.

## UX-наблюдение: анимация прилипания Windows отличается от кастомной в Tk

Наблюдение (M1-приёмка, Windows 11 24H2, два монитора): стандартная
анимация прилипания окна Windows (Aero Snap: перетаскивание к краю,
Win+стрелки, Snap Layouts при наведении на «развернуть») визуально
отличается от кастомной анимации прилипания Tk-сборки — в Tk прилипание
рисуется собственным механизмом (SnapPreview-подложка + плавная
геометрия через опрос курсора, 2.20.0), и его анимация не совпадает с
системной.

**Оценка нативного прилипания Qt (M2):**

- В Qt-сборке окно идёт со **стандартной системной рамкой** (решение
  раздела Е плана; запреты З.6: TrafficLights, SnapPreview,
  PointerPoller, WM_NCHITTEST-хуки и растягивание за кромки в Qt не
  переносятся). При нативной рамке прилипание выполняет сам оконный
  менеджер Windows: drag-to-edge, Win+стрелки, Snap Layouts — всё
  системное, включая системную анимацию. Никакого кода прилипания в
  Qt-каркас не добавляется — нативное прилипание включается само.
- Frameless-вариант Qt рассматривался и отклонён: он сохранил бы весь
  Tk-долг (самописное прилипание, опрос курсора, ручное растягивание)
  и потерял бы системные Snap Layouts.
- Вывод: различие анимации закрывается самой миграцией на нативную
  рамку. Кастомную анимацию в Qt не эмулируем — это нарушало бы З.6;
  отдельная задача не планируется. Проверка самого факта прилипания
  и уноса на второй монитор — Windows-runbook M2 (К-4, «не проверено»
  до прогона).

## M2: заметки реализации

- **Pillow вне customtkinter — не используется** (проверка В.5, M2):
  `grep from PIL|import PIL` по собственному коду проекта — пусто.
  Pillow остаётся зависимостью customtkinter (Tk-сборка) и выводится
  вместе с ним после M8.
- **PySide6 не добавляет сетевых вызовов** (проверка З.5, M2):
  модули Qt-каркаса (`main_qt.py`, `qt_theme.py`, `qt_dialogs.py`)
  не импортируют сетевые библиотеки; сеть в приложении остаётся только
  в updater.py (allowlist SEC-1 без изменений).
- **APP_UI_FLAVOR остаётся "tk" в app_common** — Qt-сборка объявляет
  себя через `main_qt.UI_FLAVOR = "qt"`; строка старта в app.log —
  «2.28.2-qt». Выбор ассета обновлений по флейвору — M7 (раздел И.2).
- **К-3 (старт/память/размер сборки)** — замеряется по Windows-runbook
  M2 через `EWDochub_qt.spec` (измерительная сборка: только иконка,
  шаблоны .docx включаются в M3/M7, чтобы замер не искажать).
- **К-4 (DPI 150%, второй монитор)** — шаги runbook M2; Qt
  масштабируется нативно, но «не заявлять решено до прогона» (риск 2).
- Таймеры опроса: QTimer на главном потоке, контракт «воркер не трогает
  UI» — дословно из раздела Д; QThread не вводим (риск 6 плана).

## M3: заметки реализации (CP1 — рабочая спецификация)

- **Чистое ядро таблицы — один источник для обеих сборок** (аналог U12
  для логики вставки): `spec_table_core.py` (GUI-free) — paste_plan
  (PERF-1), нормализация чисел, валидаторы, санитизация вставки,
  `items_from_values`. Tk `widgets.SpecTable` делегирует (API и
  поведение не изменены, `test_spec_table_validation.py` без правок);
  Qt `spec_table_qt.SpecTableQt` использует то же ядро. Дрейф лимита
  500/правил вставки между сборками исключён по построению.
- **Сохранение не копировано**: Qt-страница собирает draft (Tk-паритет
  структуры: kind/party_id/number/date/data/extra/text) и вызывает
  существующий `services.save_document` — транзакция DEF-4, предохранитель
  DEF-2, атомарная запись — общий код. Суммы — только
  `document_builder.spec_total`/`spec_vat_amount_from_items` (U12):
  строка итогов под таблицей, предпросмотр и печатная форма не могут
  разойтись по построению; тест «один spec_total» в test_spec_page_qt.
- **Предпросмотр = печатная форма** (решение раздела Е): в Tk текстовый
  предпросмотр спецификации — собственный рендер
  (document_save_controller.render_spec_preview). В Qt по плану CP1
  предпросмотр собирает печатную форму из шаблона через
  `services.build_record_docx` (путь сохранения) БЕЗ записи на диск и
  показывает текст формы (docx_to_text). Обе стороны CP1-критерия № 5
  («предпросмотр построен из шаблона», «совпадает с golden-эталоном»)
  покрыты тестами: сигнатура формы из сборки страницы == spec_ooo.json.
  Отложенная пересборка 120 мс (п. 5.6) и гард видимой страницы (P-07)
  перенесены дословно.
- **DEF-2 через контроллер недостижим на реальном шаблоне без
  позиций** — save_spec блокирует «Нет позиций» раньше (Tk-паритет).
  Поэтому Qt-тесты DEF-2 используют ту же подмену build_record_docx,
  что Tk-тесты test_services_disk (честная интеграционная проверка
  маршрута, логика guard'а покрыта сервисными тестами). Отмечено в
  докстрингах тестов.
- **Папка документов** (п. 2.8): Qt-страница использует non-interactive
  ветку той же логики (настройка «documents_dir» либо
  «Документы/EW.DocHub» через GUI-free shell_open.documents_known_folder).
  Интерактивный выбор папки — вместе со страницей «Настройки» (M6);
  недоступная папка честно отклоняет сохранение с сообщением.
  `is_inside_directory` перенесена в GUI-free services (общий источник
  с Tk SettingsController — метод сохранён, делегирует).
- **Shell-хелперы объединены** (точка M3 из докстринга M2):
  `shell_open.py` — GUI-free ядро «Открыть файл»/«Показать в папке»/
  «Документы» (контракты main.open_file п. 6.2: absent — сразу отказ,
  честный результат). Tk-версии main.open_file/show_in_folder не
  тронуты (связаны с Tk-алертом, уходят в M8).
- **EWDochub_qt.spec**: включены `spec_template*.docx` (M3-заметка M2
  выполнена); остальные шаблоны — M6.
- **Замер вставки 500 строк**: Linux offscreen — 35,2 мс (smoke_qt,
  чистая таблица). Windows-цифра — runbook M3 (риск карточки M3),
  порог выставляется после К-2.

### UX-наблюдение (M3): таблица позиций в Qt ведёт себя иначе при правке

Наблюдение реализации (Linux offscreen; Windows-сравнение — runbook M3):

- **Правка ячеек**: в Tk ячейка readonly до двойного клика, каретка
  управляется вручную; в Qt правка открывается двойным кликом
  (EditTrigger.DoubleClicked) стандартным редактором — системное
  меню правки (контекстное меню, выделение, Ctrl+A внутри ячейки) —
  поведение Qt, а не Tk. Пользователь увидит стандартные для Windows
  жесты редактирования вместо самописных Tk-механик — так же, как с
  прилипанием окна (M2-наблюдение): различие закрывается миграцией,
  эмуляция Tk-механики не выполняется.
- **Клавиатура**: Tab/стрелки между ячейками и Enter в редакторе —
  стандартные Qt-жесты; контракт Tk «Enter в таблице не сохраняет
  документ» сохранён (Ctrl+S — вне таблицы, как в Tk).
- **Вставка блока из Excel**: лимит 500 и сообщение — общий код ядра
  с Tk (spec_table_core); порядок значений в ячейках при вставке со
  сдвигом — тот же алгоритм map_row. Видимое отличие — таблица Qt
  рисует сетку/выделение в своём стиле (QSS в qt_theme), а не в стиле
  tk.Entry — стилизация QSS, риски внешнего вида — M5-риски реестра
  не применимы (SpecTableQt — QTableWidget, не Treeview).
- **Риск карточки M3** («таблица ведёт себя иначе при вставке больших
  блоков»): замер вставки 500 строк на Windows — runbook M3, шаг 6.

## M4: заметки реализации (карточка контрагента и защита данных)

- **Чистое ядро формы — один источник для обеих сборок** (аналог
  spec_table_core): `party_form_core.py` (GUI-free) — READ_ERROR_MARKER,
  FORMAT_HINTS (ключи F), read_entry_values, form_signature,
  split_read_failures, merge_saved_values, PHONE_ALLOWED_PATTERN.
  Tk `counterparty_controller` делегирует (имена сохранены, тесты Tk
  без правок); Qt `counterparty_page_qt` использует то же ядро через
  адаптеры QtEntry/QtOptionEntry (протокол .get() — Tk-протокол).
  Дрейф «сбой ≠ пустая строка» (D4) между сборками исключён.
  `services._PHONE_ALLOWED_RE` компилируется из того же паттерна —
  один источник маски телефона.
- **DaData на Qt — без копирования сети**: `dadata_qt.py` переносит
  только жизненный цикл (guard busy → HTTP → подстановка); запрос —
  тот же `dadata_client.fetch_party` (SEC-1 allowlist не расширялся,
  TLS/таймауты не тронуты). Очередь результата + опрос — именованные
  poll-таймеры каркаса (`dadata_busy` 300 мс, `dadata_result` 80 мс),
  не QThread (риск 6 плана); закрытие окна — abort() в _on_close,
  результат «в полёте» не применяется к уничтоженным полям (тихий
  отказ U8: RuntimeError уничтоженного QLineEdit = Tk TclError).
  Цель запроса — снимок DadataTargetQt (поля/режим/статус/владелец
  диалогов) — как Tk DadataTarget.
- **DEF-1 в Qt-обвязке**: сбой чтения обязательного поля блокирует
  сохранение с явным сообщением и перечнем полей; необязательного —
  явный выбор «Сохранить с прежними значениями» (merge_saved_values
  из общего ядра). Снимок окна правки — form_signature ядра: сбой
  чтения = маркер = «грязное» окно.
- **CHKSUM-паритет**: новая карточка — previous=None (все реквизиты
  новые); окно правки — previous=saved (прежние реквизиты не
  перепроверяются — старые карточки открываются и пересохраняются).
- **Задокументированные отклонения от Tk (решения M4):**
  1. После добавления каркас открывает «Спецификацию» — ближайшая
     живая страница; в Tk уход на «Договор» с выбранным контрагентом,
     «Договор» в Qt — плейсхолдер до M6 (M6 вернёт уход на договор).
  2. Временная точка входа в окно правки — кнопка «Редактировать
     карточку» на панели «Документ для» страницы «Спецификация»:
     Tk-точка (панель действий реестра) появится в M5. После M5
     решается — оставить кнопку или убрать.
  3. Кнопка сохранения «Сохранить контрагента (Ctrl+S)» — на самой
     странице: Qt-каркас M2 не строит общий футер с кнопкой (Tk
     _update_footer). **Замеченный M3-хвост: у страницы
     «Спецификация» кнопки сохранения тоже нет (только Ctrl+S)** —
     добавить вместе с футером M6-страниц (не входит в M4).
  4. V5 «обновить точки грязных страниц» после программной подстановки
     DaData не переносится: в Qt-каркасе M2/M4 точек навигации нет;
     «грязное» состояние страницы честно отражает несохранённые
     реквизиты (baseline не сбрасывается).
- **Наблюдение тестовой инфраструктуры (M4)**: обычный
  `processEvents` не сбрасывает отложенные удаления Qt (DeferredDelete) —
  фикстура M4 закрывает окно каркаса и делает явный flush
  `sendPostedEvents(None, DeferredDelete)`: без него время setup
  росло линейно (0,12 → 4,5 с на 47 тестов), с flush — плоско
  (~0,03 с). Фикстуры M2/M3 не трогались (не входят в этап); та же
  две строки могут быть применены к ним в M5+ отдельной правкой.

### UX-наблюдение (M4): правка карточки в Qt — стандартные жесты поля

Наблюдение реализации (Linux offscreen; Windows-сравнение — runbook M4):

- **Поля ввода**: QLineEdit — системные жесты правки (контекстное меню,
  Ctrl+A/Ctrl+Z/Ctrl+V внутри поля, двойной клик — выделение слова)
  вместо самописных Tk-механик validatecommand/каретки. Контракты
  сохранены кодом: валидатор «только цифры, не длиннее max_len» —
  QRegularExpressionValidator + setMaxLength; вставка с очисткой
  (аудит 2.0.1) — переопределённый insertFromMimeData (из буфера —
  только допустимые символы, как enable_sanitized_paste); маска
  телефона — тот же алгоритм format_phone с поправкой курсора.
- **Подсказки формата** (U4) — placeholderText пустого поля: в карточку
  не попадают, как в Tk (get пустого поля — пустая строка).
- **Переключатель ООО/ИП** — пара checkable-кнопок (QSS segment)
  вместо ui.segmented; состояние — то же «Юр. лицо»/«ИП», поведение
  tkraise — QStackedWidget.
- **Окно правки** — модальный QDialog (window-modal) вместо
  CTkToplevel + grab_set; Escape/крестик — единый guard DEF-1
  (переопределённый reject), деструктивная семантика: Enter —
  «Вернуться к правке», данные не теряются (U7).
- **Подсветка ошибок** — errorState-свойство поля (красная рамка QSS) +
  подписи под полями; фокус на первое ошибочное поле (U5), как в Tk.
- Windows-сравнение жестов/маски/вставки — runbook M4 (шаги 6–8),
  «не проверено» до прогона.

## M5: заметки реализации (реестр на Qt, TREE-1/UX-REG)

- **Чистое ядро реестра — один источник для обеих сборок** (аналог
  spec_table_core/party_form_core): `registry_core.py` (GUI-free) —
  RowSpec/DiffPlan, plan_diff (алгоритм и O(n)-оптимизация перенесены
  дословно с комментарием профилировщика), plan_display_count, лимит
  DISPLAY_SOFT_LIMIT = 10 000 («не трогаем», запрет З.2), SHOW_MORE_IID,
  колонки/сортировки/фильтры/точки/ACTION_LABELS, чистые построители
  значений строк. Tk `registry_tree` и `registry_controller` делегируют
  (имена сохранены, тесты Tk без правок — прогон 70/70); Qt строит
  QAbstractTableModel из тех же RowSpec. Дрейф «данные ↔ отображение»
  между сборками исключён по построению.
- **Диф в Qt — план без Tk, исполнение сигналами**: plan_diff даёт
  (удалить, операции, обновить); модель исполняет его через
  beginRemoveRows/beginInsertRows/dataChanged. Неизменённые строки не
  пересоздаются (критерий 5.1) — выделение переживает «Показать ещё»
  и правки (тест). «Move» из плана исполняется парой
  снять-и-вставить (семантика Tk tree.move) — гарантированно совпадает
  с симуляцией плана; Qt moveRows не используется из-за расхождений
  семантики destination-индекса.
- **Теги сроков и точки**: expired/soon — ForegroundRole с живым
  чтением текущей темы (эквивалент Tk-перекраски по слушателю темы);

## M6: заметки реализации (договор, доп. соглашение, импорт, START-1, настройки)

Этап M6 (коммиты 3c015b6 / 0e6345d / 9360e4f / b18a049 / 9c43f78 / 6d7e84f)
закрывает сценарии Г #4, #5, #13, #14, #15, #16: живыми стали все шесть
разделов каркаса. Ниже — решения и отличия от Tk, зафиксированные для
протокола К-1/К-2.

- **Единый текущий контрагент — fan-out каркаса** (п. 4.2). В Tk выбор
  синхронизирует DocumentContextController через StringVar; в Qt владелец —
  AppController.set_current_party(rec, source): обходит живые потоки
  (spec/contract/additional), страница-источник пропускается, guard
  ``_syncing_party`` исключает обратную рекурсию из on_party_changed.
  Комбо обновляются с заблокированными сигналами — пользовательский
  маршрут не срабатывает повторно. На старте страницы строятся по очереди:
  spec может транслировать выбор до создания M6-потоков (база с данными) —
  fan-out читает потоки через getattr.
- **Предпросмотры договора/доп. соглашения** — таймер 120 мс (п. 5.6,
  Tk-паритет) и рендер только при видимой странице (P-07); при
  переключении их пересобирает on_page_open. Курсор при переформатировании
  лимита — setCursorPosition с поправкой на разряды (Tk
  restore_caret_after_reformat).
- **LAZY-1** сохранён по построению: предпросмотр и сохранение доп.
  соглашения дочитывают тело ленивого договора единым getter'ом
  store.document_body; экспорт из реестра собирает печатную форму из
  дочитанного тела (тест test_export_after_lazy_load_returns_full_text).
- **Импорт** (import_qt.py) — дословный перенос import_controller:
  guard в начале запуска, своя очередь у запуска (воркеру через args),
  allowlist .docx/.xlsx, U9-сводка (один диалог на серию без ИНН + один
  на конфликты названий), пакетная запись одним save(), unknown для
  отклонённых копий, отчёт с «Открыть реестр» (U10). Отличия: окно
  прогресса и отчёт — QDialog; drag&drop — нативный Qt на MainWindow
  (Win32-хуки WM_DROPFILES Tk не переносятся, К-3 не задействован);
  выбор файлов — QFileDialog.getOpenFileNames.
- **START-1** (startup_qt.py) — перенос startup_controller: read-only
  воркер (temp → trash_plan → orphans → notice), результаты применяются
  только в главном потоке (опрос QTimer 80 мс), флаг остановки между
  шагами, perf-каналы startup.* те же. TRASH-WARN: сводка «будет удалено
  N» в журнале ДО удаления, итог — тост + статус. Сверка (DEF-3):
  scan_consistency + баннер «файлов вне реестра» с кнопкой «Разобрать»;
  диалог «Восстановить в реестр»/«В корзину» — дословно Tk-тексты
  (D1 — честные счётчики при сбое записи). Суточный гейт уведомления о
  сроках — прежний ключ settings.json last_expiry_notice.
- **Настройки** (settings_page_qt.py) — тема радиопарой (одна подписка на
  переключение: две подписки давали бы двойной set_theme; индикаторы
  синхронизируются слушателем с заблокированными сигналами), папка
  документов с немедленным сохранением (save_setting возвращает результат
  записи — Tk-паритет _persist_settings: «Папка сохранена» только при
  записи), ключ DaData без подстановки сохранённого значения (аудит
  2.0.1), копии BKUP-1 со статусом (стартовая автокопия —
  QTimer.singleShot(400) — прежняя точка Tk root.after(400)).
- **Карточка «Обновления»** на странице настроек — не перенесена (M7:
  UI обновлений идёт отдельным этапом с оркестрацией updater_controller
  на QTimer); это единственный недостающий блок Tk-страницы настроек.
- **Стабилизация 10k-теста реестра**: M6-кнопка «Добавить документы…»
  изменила высоту шапки — после смены фильтра первая компоновка сдвигает
  максимум скроллбара на тик; прокрутка в тесте сделана двухпроходной
  (равна реальной прокрутке до конца), смысл проверки сохранён.

### UX-наблюдение (M6): страницы документов в Qt

Наблюдение реализации (Linux offscreen/Xvfb; Windows-сравнение — runbook M6):

- **Комбо контрагентов** — QComboBox с системным поведением (клавиатура,
  колесо, выпадающий список с прокруткой); в Tk — самописный

  курсора; в Tk то же поведение обеспечивалось after_idle-хаком каретки,
  в Qt курсор ставится синхронно.
- **Прогресс импорта** — QDialog с QProgressBar; Escape не закрывает
  (отмена — только кнопкой, как grab_set в Tk).
- Windows-проверка DPI 150%, перетаскивания файлов и модальности —
  runbook M6, «не проверено» до прогона.
